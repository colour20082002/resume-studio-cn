# 按 JD 定制简历

目标不是改写成另一份简历，而是让同一批真实经历按目标岗位的优先级重新排序、重新措辞。

## 流程
1. 读 JD，提取三类词：
   - 硬性要求：行业、年限、证书、工具（如「保险」「Excel」「风控」）。
   - 职责动词：搭建、统筹、分析、维护、推动、复盘。
   - 结果指标：坏账率、满意度、转化率、成本、时效。
2. 对照 `resume.yml` 做证据映射，每个 JD 关键词找到一条真实经历。找不到的不要硬编。
3. 调整顺序：
   - `summary` 首句改成 JD 的岗位方向。
   - `competencies` 把与 JD 最相关的 3 条放前面。
   - `experience` 每段的 bullets 把最贴近 JD 的放第一条，最多保留 5–6 条。
4. 措辞对齐：JD 用「客户服务」，简历就不要只写「客诉处理」；但只改词，不改事实。
5. 跑校验：
   ```bash
   py -3 scripts/check.py --root <内容目录> --pages 2 --keywords "关键词1,关键词2,关键词3"
   ```

## 评分参考（0–5）
- 5：JD 的核心要求全部有直接证据，且近三年经历匹配。
- 4：核心要求大部分匹配，个别靠相邻经验补。
- 3：方向一致但证据偏弱，需要重写 bullets 才能投。
- 2 及以下：不建议投，改投相邻岗位。

## 边界
- 不编造经历、不夸大数字、不改在职时间。
- 不为一份 JD 删掉整段真实经历，除非明确与岗位冲突且篇幅紧张。
- 同一份 `resume.yml` 只保留一个主方向；跨方向投递时复制目录再改，不要在一份里塞两个方向。
- 输出前确认 `check.py` 为 PASS，且 PDF 页数符合预期（通常 2 页）。
